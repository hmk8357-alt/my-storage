# 배포 전 1차 검토

2026-11-07. Firebase 백엔드 배포 완료. GitHub 소스 업로드와 Pages 공개는 권한 연결 후 진행한다.

## 확인한 문제

1. 배포 작업 폴더에는 .git만 있고 소스가 없다. 사용자가 주변 폴더의 교사용 허브와 일기장 연결을 확인했다.
2. 교사용 허브는 GAS 템플릿과 google.script.run 기반 서버 호출을 사용한다. Pages에 원본을 복사하는 것만으로는 작동하지 않는다.
3. 일기장은 로컬 HTTP/SQLite 서버를 사용한다. 공개용으로는 인증과 사용자별 데이터 격리를 새로 구현해야 한다.
4. 원본 일기장의 data/에 실제 저장소가 존재한다. 내용을 읽지 않았으며 공개 대상에서 제외해야 한다.
5. 원본 허브에는 .tools/, .clasp.json이 있다. 인증 도구·로컬 연결 설정을 공개 대상에 포함하지 않는다. 인증 토큰 파일의 내용은 읽지 않았다.
6. 원본 개인정보 안내는 명시적으로 초안이다. 운영 주체·연락처·보존기간·학생 및 아동 처리 사실이 미확정이며 공개용 최종 방침으로 간주할 수 없다.
7. 연결 GitHub 계정 조회는 가능했지만 커넥터에서 접근 가능한 저장소 목록이 비어 있었다. 새 저장소 생성 및 Pages 설정은 별도 수단의 로그인·권한을 확인해야 한다.

## 남은 검증

- 공개할 파일 목록을 확정한 뒤 비밀정보·개인정보 검사.
- Firebase 실제 프로젝트의 인증 제공자·허용 도메인·데이터베이스·규칙 배포 확인.
- 비로그인 및 다른 사용자 접근 거부에 대한 규칙 테스트.
- GitHub Pages 하위 경로, 로그인, 작성·수정·삭제·복원 및 로그아웃 검증.

이는 원본 구조와 문서를 대상으로 한 1차 검토이며 보안 검증 완료 판정이 아니다.

## 구현 및 백엔드 배포 검증

- Firebase 프로젝트 `teacher-diary-hub-20261107`와 웹 앱 생성 완료.
- 사용자 승인 후 Google 로그인 제공자, Pages 도메인 `hmk8357-alt.github.io`, Firebase 인증 처리 주소와 localhost 연결 설정 배포 완료. 실제 브라우저 로그인은 Pages 배포 후 검증한다.
- 사용자가 천안을 사용할 수 없으면 서울을 사용하도록 승인했다. 기본 데이터베이스는 `asia-northeast3`, `STANDARD`, `FIRESTORE_NATIVE`, `freeTier: true`임을 공식 CLI로 확인했다. 청구 계정은 연결하지 않았다.
- 실제 Firestore 보안 규칙 컴파일, 규칙과 인덱스 배포 성공.
- Node 도메인 테스트 4개 통과: 입력·날짜·태그, 백업 검증, 계정 세대 변경, 401편 백업 분할 및 바이트 제한.
- 로컬 Firestore 에뮬레이터 테스트 4개 통과: 본인 CRUD, 비로그인·타계정·비Google 인증 차단, 생성/수정 스키마 검증, 생성시각 변경·공개 프로필·임의 경로 차단. 가상 데이터만 사용했다.
- 독립 코드 검토에서 초기 로딩 중 초안 덮어쓰기, 삭제 중 입력 손실, 복원 한도보다 큰 백업 생성 문제를 확인하고 수정했다. 백업 파일은 200편·5MB 제한에 맞춰 분할되며 사용자가 모든 파일을 내려받을 수 있다.
- 처음 GitHub 쓰기가 `403 Resource not accessible by integration`으로 거부됐으나 사용자가 공식 연결 앱을 설치한 뒤 README 생성 성공으로 쓰기 권한을 확인했다. 공개 대상 저장소는 `hmk8357-alt/my-storage`다.
- 실제 SQLite, 학생 자료, 백업, 토큰은 읽거나 복사하지 않았다. 공개 파일 목록에 `.tools/`, 인증 연결 설정, SQLite가 없음을 확인했다.
- Firebase 승인 도메인 화면에서 `hmk8357-alt.github.io`, `teacher-diary-hub-20261107.firebaseapp.com`, 기본 `web.app`과 `localhost`를 실제로 확인했다.
- 남은 항목: GitHub 전체 소스 업로드 및 Pages 공개, 실사용자 Google 로그인과 클라우드 저장 UI 검증.
